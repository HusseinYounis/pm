13.1 Basic Principles of Cost Management 📋 Required

Before estimating or controlling costs, project managers must understand the fundamental cost concepts that underpin financial decision-making:

13.1.1 What is Cost?

Cost is a resource sacrificed or foregone to achieve a specific objective — usually measured in monetary units. Project cost management encompasses all processes required to complete the project within an approved budget.

13.1.2 Key Cost Concepts

  • Types of Costs
  • Life Cycle Costing
  • Financial Return Concepts
  • Learning Curve Theory
  • Reserves

13.1.3 1. Direct vs. Indirect Costs

Note💼 Direct Costs

Expenses that can be attributed entirely and specifically to a single project. These do not exist if the project does not happen.

Example Description
Specialized team salaries Staff hired solely for this project
Project hardware/software licences Purchased exclusively for project use
Raw materials Consumed directly in deliverables
Contractor fees Engaged specifically for project work
Tip🏢 Indirect Costs

Overhead or administrative costs that support general business operations rather than a specific project. Usually shared across multiple projects.

Example Description
Office rent Facility housing all teams
General utilities Power, internet, water
Executive salaries Leadership overseeing all projects
Insurance Organisation-wide cover

13.1.4 2. Fixed vs. Variable Costs

Note📌 Fixed Costs

One-off or recurring expenses that remain constant regardless of the project’s production level, output, or timeframe.

Example Description
Software subscriptions Same monthly fee regardless of usage
Consultant retainers Fixed monthly engagement fee
Equipment lease agreements Fixed periodic payment
Tip📈 Variable Costs

Expenses that fluctuate or scale based on the level of project activity, resources used, or overall volume.

Example Description
Temporary worker wages More workers = higher cost
Materials consumed Concrete, steel — quantity-driven
Shipping fees Scales with volume and distance

13.1.5 3. Additional Cost Classifications

Cost Type Definition Key Rule / Example
Sunk Costs Money already spent and unrecoverable ⚠️ Never let sunk costs influence future decisions — e.g. funds spent on a cancelled prototype or a failed software platform
Opportunity Costs The potential value or revenue lost by choosing one project over an alternative Choosing Project A means forgoing the benefit Project B would have delivered
Recurring Costs Repetitive expenses incurred regularly Weekly labour costs, monthly software subscriptions
Non-Recurring Costs One-time upfront investments Initial hardware setup, site mobilisation
Quality Costs Expenses dedicated to ensuring quality standards are met Prevention (training), Appraisal (testing), Failure (rework, warranty claims)
Contingency Reserves Funds set aside for known risks or scope changes within the project’s baseline budget Controlled by the PM; part of the cost baseline
Important⚠️ The Sunk Cost Trap

A common decision-making error is allowing sunk costs to drive future spending. The fact that ₪500,000 has already been spent on a failing system is irrelevant to the question of whether to continue — only the future costs and benefits of each option should guide the decision.

Life cycle costing (LCC) considers the total cost of ownership across the asset’s entire life — not just the capital construction cost:

\[LCC = C_{initial} + C_{operations} + C_{maintenance} + C_{disposal} - C_{salvage}\]

Important⚠️ Why LCC Matters

A pump that costs $8,000 to purchase but \(3,000/year to maintain over 20 years has a life cycle cost of:\)\(LCC = \$8,000 + (20 \times \$3,000) = \$68,000\)$

A $12,000 pump requiring only \(1,200/year has:\)\(LCC = \$12,000 + (20 \times \$1,200) = \$36,000\)$

The “cheaper” pump costs 89% more over its service life. LCC prevents false economy in procurement.

Senior management and clients evaluate projects using financial metrics. Project managers must speak this language:

Term Definition Formula
Revenue Income generated from the project’s outputs —
Profit Revenue minus all expenditures \(Profit = Revenue - Cost\)
Profit margin Ratio of profit to revenue (expressed as %) \(PM = \frac{Profit}{Revenue} \times 100\)
Return on Investment (ROI) Benefit of investment relative to its cost \(ROI = \frac{(Benefits - Costs)}{Costs} \times 100\%\)
NPV Net Present Value — sum of discounted future cash flows \(NPV = \sum \frac{CF_t}{(1+r)^t}\)
Payback Period Time to recover initial investment \(PP = \frac{Initial\ Investment}{Annual\ Net\ Benefit}\)

A positive NPV means the project creates value. A higher ROI indicates better return per dollar invested.

Learning curve theory states that as workers gain experience producing a product, unit cost decreases in a predictable pattern. Each time cumulative output doubles, cost per unit falls by a fixed percentage.

\[Unit\ Cost_n = Unit\ Cost_1 \times n^b \quad \text{where } b = \frac{\log(learning\ rate)}{\log(2)}\]

Learning Rate Meaning
80% Each time production doubles, unit cost = 80% of previous
90% Unit cost = 90% of previous each doubling

Example: If the first unit costs $100,000 and the learning rate is 80%, the 2nd unit costs $80,000; the 4th unit costs $64,000; the 8th costs $51,200.

Project implication: Software development, prefabrication, and repetitive construction activities all exhibit learning curve effects — factor this into estimates for repetitive work.

Reserves are funds included in a cost estimate to mitigate risk:

Reserve Type Purpose Who Controls
Contingency Reserve Known-unknowns — identified risks with probability and impact Project Manager
Management Reserve Unknown-unknowns — unforeseeable events Senior Management / Sponsor

Contingency is part of the cost baseline; management reserve is NOT in the cost baseline but IS in the project budget.

13.2 Cost Estimation 📋 Required

Cost estimation is the process of predicting the financial cost of completing project work.

13.2.1 Estimation Classes (فئات تقدير التكلفة) — AACE International Standard

The AACE International Cost Estimate Classification System categorises capital project cost estimates into five distinct classes (Class 1 through 5) based on the maturity of project definition deliverables (نضج مخرجات تعريف المشروع) — not merely elapsed time or estimate purpose. It provides a standardised stage-gate framework that aligns estimate accuracy and methodology with the degree of project scope development.

Note📌 Three Key Rules of the System
  1. Primary determinant is scope maturity — the class assigned depends on how complete the project definition deliverables are, not the phase name or calendar date.
  2. Accuracy ranges (نطاق الدقة) are not universal — they depend on technological complexity, quality of historical data, and defined risk levels.
  3. Scope changes are excluded — accuracy percentages represent normal variation within a defined scope; they do not cover scope growth.

13.2.2 Estimation Techniques (أساليب تقدير التكلفة)

  • Analogous (Top-Down)
  • Parametric
  • Bottom-Up
  • Three-Point (PERT)

13.2.3 التقدير بالمقارنة / التناظري (Analogous — Top-Down)

Based on historical data from similar past projects — الاعتماد على البيانات التاريخية لمشروع سابق مماثل لتقدير تكلفة أو مدة المشروع الحالي.

\[Cost_{new} = Cost_{historical} \times Adjustment\ Factor\]

When to use Very early project stages — Class 5 / Class 4 — when design details are almost non-existent (المراحل الأولية جداً عندما تكون التفاصيل شبه معدومة)
Advantages (المميزات) Very fast · Low cost · Requires minimal engineering effort
Disadvantages (العيوب) Very low accuracy — assumes similar conditions, location, and inflation rates, which rarely holds true (يفترض تشابه الظروف والموقع والتضخم، وهو ما لا يحدث غالباً)
Tip💡 Simple Example — Painting a School Classroom

Situation: You need to estimate the cost of painting a new classroom (60 m²). You have no detailed plans yet — only the room size.

Historical data: Last year you painted a similar classroom of 50 m² for ₪2,500.

Step 1 — Calculate the historical unit rate: \[Unit\ Rate = \frac{\text{₪}2{,}500}{50\ m^2} = \text{₪}50\ per\ m^2\]

Step 2 — Apply to the new project: \[Cost_{new} = \text{₪}50/m^2 \times 60\ m^2 = \mathbf{\text{₪}3{,}000}\]

Interpretation: Based on the last job, painting this classroom should cost around ₪3,000. This took 2 minutes to calculate — but accuracy is only ±30% to ±50%. The real cost could be anywhere from ₪1,500 to ₪4,500 depending on paint quality, number of coats, and labour rates. Use this number only for early budget screening.

Cost Capacity Factor — Six-Tenths Rule (قاعدة الأعشار الستة): \[Cost_B = Cost_A \times \left(\frac{Capacity_B}{Capacity_A}\right)^{0.6}\]

Engineering example: A 50 ML/day desalination plant cost \(85M. Estimating a 65 ML/day plant:\)\(\$85M \times (65/50)^{0.6} = \$85M \times 1.21 \approx \$103M\)$

Accuracy (نطاق الدقة): ±25% to ±50%

13.2.4 التقدير البارامتري / الإحصائي (Parametric)

Uses a statistical relationship between historical data and project parameters to calculate cost — استخدام علاقة إحصائية بين البيانات التاريخية والمتغيرات الأخرى (البارامترات) لحساب التكلفة، مثل: تكلفة المتر المربع × المساحة الكلية.

\[Cost = Unit\ Rate \times Quantity\ of\ Parameter\]

When to use Early to mid stages — Class 4 / Class 3 — e.g. estimating hospital construction costs based on number of beds (تقدير تكلفة بناء المستشفيات بناءً على عدد الأسرة)
Advantages (المميزات) More accurate than analogous estimating · Easy to adjust and scale using software
Disadvantages (العيوب) Entirely dependent on model quality — if historical data or equations are wrong, the result will be incorrect (إذا كانت البيانات القديمة أو المعادلات خاطئة، ستكون النتيجة غير صحيحة)
Tip💡 Simple Example — Painting a School (Multiple Classrooms)

Situation: You need to paint an entire school — 12 classrooms, a corridor, and a staff room. You now have the floor plan (areas known) but no detailed specifications. You use published unit rates from similar school projects.

Area Unit Rate Quantity Estimated Cost
Classrooms (standard) ₪50/m² 12 × 60 m² = 720 m² ₪36,000
Corridor (high-traffic, extra coats) ₪65/m² 150 m² ₪9,750
Staff room (feature wall) ₪80/m² 40 m² ₪3,200
Total Parametric Estimate ₪48,950

Interpretation: The parametric model gives a much better breakdown than the analogous single number. You can see where costs come from — and changing one rate (e.g. if corridor paint is more expensive) instantly updates the total. Accuracy is ±10–25%: far better than the analogous estimate, but a detailed take-off would still be more precise.

Accuracy (نطاق الدقة): ±10% to ±25%

13.2.5 التقدير من أسفل إلى أعلى (Bottom-Up)

Bottom-up estimating builds the total project estimate by estimating each individual task, activity, or work package separately — then rolling all those estimates upward into a project total.

تفكيك المشروع إلى أصغر أجزاء ممكنة (حزم العمل في هيكل تقسيم العمل WBS) وتخمين تكلفة كل بند على حدة، ثم تجميعها تصاعدياً للوصول لإجمالي المشروع.

When to use Advanced, engineering-complete stages — Class 2 / Class 1 (المراحل المتقدمة والمكتملة هندسياً)
Advantages (المميزات) Most accurate technique · Provides full detail supporting cost control during execution (الأدق على الإطلاق، ويوفر تفاصيل كاملة تدعم الرقابة على التكاليف أثناء التنفيذ)
Disadvantages (العيوب) Time-consuming · Very costly to prepare · Requires complete engineering documents (يستهلك وقتاً طويلاً، مكلف جداً لإعداده، ويتطلب وثائق هندسية مكتملة)

Situation: The school contract is now finalised. You must submit a priced tender for painting one standard classroom (60 m²). You count every litre of paint, every hour of labour, every tool.

Scale this up across 12 classrooms + corridor + staff room and the bottom-up total would be far more reliable than ₪48,950 from the parametric approach.

The 4-Step Process (خطوات التطبيق)

Step Action What to Do
1 — Break Down (تفكيك المشروع) Create a WBS (هيكل تقسيم العمل) Split the project into work packages — the road map of individual tasks to estimate
2 — Estimate Each Package (تقدير كل حزمة) Consult team & experts For each work package, determine time, cost, and resources. Consult developers, engineers, designers
3 — Aggregate (التجميع التصاعدي) Sum all estimates Add all work package estimates to produce the total project cost
4 — Review & Refine (المراجعة والتحسين) Validate with stakeholders Adjust using historical data or expert judgement; confirm with sponsor

For each work package — مكوّنات تكلفة كل حزمة عمل:

  1. Materials (المواد): Quantity × Unit rate
  2. Labour (العمالة): Hours × Hourly rate
  3. Equipment (المعدات): Hours/days × Hire rate
  4. Overheads (المصاريف العامة): (L + M + E) × OH%
  5. Profit/margin (الربح) — for contractors

Benefits (المميزات)

Benefit Explanation
High accuracy (دقة عالية) No big assumptions — every task is individually examined
Better risk identification (كشف المخاطر مبكراً) Task-level breakdown exposes cost and schedule risks before they escalate
Stakeholder confidence (ثقة أصحاب المصلحة) Detailed, evidence-based estimates are far easier to defend and gain buy-in for

Drawbacks (العيوب)

Drawback Impact
Time-consuming (يستغرق وقتاً طويلاً) Estimating every task separately is a project in itself for large programmes
Requires many inputs (يحتاج مدخلات كثيرة) Coordination across team members, experts, and stakeholders adds overhead
Risk of over-detailing (خطر الإفراط في التفصيل) Too deep a WBS decomposition makes estimates hard to track and maintain

Accuracy (نطاق الدقة): ±5% to ±15%

13.2.6 التقدير ثلاثي النقاط (Three-Point Estimation — PERT)

A technique to reduce risk and uncertainty by considering three scenarios instead of a single fixed number — تقنية لتقليل المخاطر وعدم اليقين عبر أخذ ثلاثة سيناريوهات في الاعتبار بدلاً من رقم واحد ثابت.

Scenario Symbol Arabic Description
Optimistic O المتفائل Best-case scenario — everything goes perfectly
Most Likely M الأكثر احتمالاً Realistic scenario under normal conditions
Pessimistic P المتشائم Worst-case scenario — major risks materialise

PERT Weighted Average Formula (المعادلة الموزونة):

\[CE = \frac{O + 4M + P}{6}\]

The Most Likely estimate is weighted four times more than the Optimistic or Pessimistic — reflecting that realistic conditions are far more probable than extremes.

Standard Deviation (الانحراف المعياري) — measure of uncertainty:

\[\sigma = \frac{P - O}{6}\]

A large \(\sigma\) means high uncertainty; a small \(\sigma\) means the three estimates are close together and the outcome is more predictable.

Tip💡 Simple Example — Painting a Classroom: How Long Will It Take?

Situation: You are planning to paint the classroom but you are unsure how many days it will take. You ask your painter, who gives you three honest answers:

Scenario Symbol Days Reasoning
Optimistic O 2 days Surface is clean, paint arrives on time, no interruptions
Most Likely M 4 days Normal conditions — some prep work, one afternoon break
Pessimistic P 10 days Wall cracks found, paint delivery delayed, extra coats needed

Step 1 — PERT weighted average: \[CE = \frac{O + 4M + P}{6} = \frac{2 + (4 \times 4) + 10}{6} = \frac{2 + 16 + 10}{6} = \frac{28}{6} \approx \mathbf{4.67\ days}\]

Step 2 — Standard deviation (how uncertain is this estimate?): \[\sigma = \frac{P - O}{6} = \frac{10 - 2}{6} = \frac{8}{6} \approx \mathbf{1.33\ days}\]

Interpretation: Rather than simply saying “4 days” (most likely), the PERT estimate gives 4.67 days — pulled upward by the pessimistic scenario. The standard deviation of 1.33 days tells you there is meaningful uncertainty: plan for 5–6 days to be safe. If the painter said O=3, M=4, P=5, the σ would be only 0.33 — very predictable. The wider the gap between O and P, the riskier the estimate.

Apply to cost: Using the bottom-up rate of ₪25/hr × 8 hrs/day: \[CE_{cost} = 4.67\ days \times 8\ hrs \times \text{₪}25/hr = \mathbf{\text{₪}934}\]

vs. the most-likely-only estimate of 4 × 8 × ₪25 = ₪800 — the PERT approach adds ₪134 as implicit risk buffer.

Used to build cost contingency (ميزانية الطوارئ) from risk analysis.

Accuracy (نطاق الدقة): ±10% to ±15% (when combined with realistic risk data)

13.5 Earned Value Management (EVM) 📋 Required

Earned Value Management (EVM) integrates scope, schedule, and cost into a single measurement system — giving you an objective view of project status at any point.

13.5.1 The Three Core EVM Values

Note📖 The Three Fundamental EVM Metrics
Metric Acronym Old Name Question it Answers
Planned Value PV BCWS How much work was planned to be done (in $)?
Earned Value EV BCWP How much work has actually been accomplished (in $)?
Actual Cost AC ACWP How much have we actually spent (in $)?

13.5.2 Rate of Performance (RP)

Rate of Performance (RP) is a practical alternative to the standard EV calculation when the precise % complete of an activity is uncertain. It compares actual work completed to the work that should have been done by now:

\[RP = \frac{\text{Actual work completed}}{\text{Work planned to be completed}} \times 100\%\]

\[EV = RP \times PV\]

Tip💡 RP Example

Activity A is planned to take 10 days and is budgeted at $5,000. After 5 days (50% of planned time), the team has completed 3 days of work (30% of the planned work).

\[RP = \frac{3}{5} = 60\%\]

\[EV = 60\% \times \$2,500 = \$1,500\]

(Note: $2,500 = PV at status date = 50% of $5,000)

RP is especially useful for activities where measuring % complete is subjective — it grounds the earned value calculation in planned vs. actual work quantities.

13.5.3 EVM Formulas Reference Card

EVM Formulas Quick Reference
Metric Formula Positive = Good Negative = Bad
SV (Schedule Variance) \(EV - PV\) Ahead of schedule Behind schedule
CV (Cost Variance) \(EV - AC\) Under budget Over budget
SPI (Schedule Performance Index) \(EV / PV\) > 1 = ahead < 1 = behind
CPI (Cost Performance Index) \(EV / AC\) > 1 = under budget < 1 = over budget
EAC (Estimate at Completion) \(BAC / CPI\) — —
ETC (Estimate to Complete) \(EAC - AC\) — —

Note🗺️ Before the Numbers: A Story First

EVM can feel like a wall of formulas — until you tie each one to something real. Imagine you are driving from Tulkarem to Jenin — two cities in the West Bank, roughly 60 km apart. You planned the trip carefully, estimated fuel, food, and tolls, and set a budget of ₪10 per km. You are the project manager of this journey.

\[\text{Budget at Completion (BAC)} = 60\ \text{km} \times \text{₪}10/\text{km} = \text{₪}600\]

13.5.4 Step 1 — Planning the Trip (PV, EV, AC)

By midday you had planned to cover 24 km of the route. That is your Planned Value (PV) — the budgeted cost of work you planned to accomplish by this point.

\[PV = 24\ \text{km} \times \text{₪}10 = \text{₪}240\]

But in reality, checkpoints and traffic on Road 60 slowed you down. You have only driven 20 km so far. That is your Earned Value (EV) — the value of work you actually completed, expressed in budget terms.

\[EV = 20\ \text{km} \times \text{₪}10 = \text{₪}200\]

Now check your wallet. Fuel, a snack at a roadside stand, and a parking fee at the checkpoint total ₪180 spent. That is your Actual Cost (AC).

\[AC = \text{₪}180\]

Tip📌 Quick Recap — The Three Core Values
Metric What It Represents Value
PV — Planned Value Work you planned to do by now ₪240 (24 km planned)
EV — Earned Value Work you actually completed ₪200 (20 km driven)
AC — Actual Cost Money you actually spent ₪180 spent

On paper you should be at 24 km, but you are only at 20 km — yet you have spent less than expected. Let’s see what the numbers tell us.

13.5.5 Step 2 — Are You On Schedule? On Budget? (SV & CV)

Schedule Variance (SV)

SV tells you whether you are ahead or behind your travel plan.

\[SV = EV - PV = \text{₪}200 - \text{₪}240 = \mathbf{-\text{₪}40}\]

A negative SV means you are behind schedule — you are 4 km (₪40 worth of distance) behind where you planned to be.

Cost Variance (CV)

CV tells you whether you are spending more or less than expected for the work done.

\[CV = EV - AC = \text{₪}200 - \text{₪}180 = \mathbf{+\text{₪}20}\]

A positive CV means you are under budget — you spent ₪20 less than the budget for the 20 km you have completed. Your roadside snack cost less than expected!

Important⚠️ Variance Summary
Variance Formula Result Meaning
SV (Schedule Variance) EV − PV −₪40 🟠 Behind schedule (4 km behind plan)
CV (Cost Variance) EV − AC +₪20 🟢 Under budget (₪20 saved so far)

Rule: Negative = Bad · Positive = Good · Zero = Exactly on plan

13.5.6 Step 3 — How Efficiently Are You Travelling? (SPI & CPI)

Variances tell you the gap in money terms. Performance indices tell you the ratio — how efficiently you are working compared to the plan. They are unit-free numbers that allow comparisons across projects of any size.

Schedule Performance Index (SPI)

\[SPI = \frac{EV}{PV} = \frac{\text{₪}200}{\text{₪}240} = \mathbf{0.833}\]

An SPI of 0.833 means you are completing 83.3% of the planned distance for every kilometre planned. For every 10 km you should drive, you are only covering about 8.3 km. You are running at 83% of your planned pace.

Cost Performance Index (CPI)

\[CPI = \frac{EV}{AC} = \frac{\text{₪}200}{\text{₪}180} = \mathbf{1.111}\]

A CPI of 1.111 means for every ₪1 you spend, you get ₪1.11 worth of distance. Your driving is cost-efficient — you are stretching the budget beyond what was planned.

Note📊 Index Interpretation Guide
Index Value Condition Plain English
SPI 0.833 < 1 ⚠️ Behind schedule Driving slower than planned — arrive late
CPI 1.111 > 1 ✅ Under budget Spending less per km than budgeted — saving money

EVM tells two stories at once: How fast you are going (SPI) and how wisely you are spending (CPI). Here you are running late but saving money — a common real-world situation.

13.5.7 Step 4 — How Will the Whole Trip End? (EAC Forecasts)

So far you have driven 20 km and spent ₪180. You still have 40 km left to Jenin. What will the total trip cost be? EVM offers four forecasting methods, each reflecting a different assumption about your future behaviour.

Known values going into the forecast: BAC = ₪600 · EV = ₪200 · AC = ₪180 · CPI = 1.111 · SPI = 0.833

EAC Formula 1 — Current efficiency continues

“I have been driving efficiently and plan to keep it that way — same fuel habits, same stops, all the way to Jenin.”

\[EAC_1 = \frac{BAC}{CPI} = \frac{\text{₪}600}{1.111} = \mathbf{\text{₪}540}\]

If you maintain your current cost efficiency for the remaining 40 km, you will arrive in Jenin having spent only ₪540 — saving ₪60 against the original budget.

EAC Formula 2 — Early savings were temporary

“I was frugal at the start, but from here I will drive at exactly the original budgeted rate — ₪10 per km for the remaining distance.”

\[EAC_2 = AC + (BAC - EV) = \text{₪}180 + (\text{₪}600 - \text{₪}200) = \text{₪}180 + \text{₪}400 = \mathbf{\text{₪}580}\]

You will finish the trip spending ₪580 — still ₪20 under the original budget, but you gave up most of your early savings.

EAC Formula 3 — Both schedule and cost delays continue

“Checkpoints and slow traffic will follow me all the way. My CPI and SPI will remain the same — I am both slow and (luckily) cost-efficient.”

\[EAC_3 = AC + \frac{BAC - EV}{CPI \times SPI} = \text{₪}180 + \frac{\text{₪}400}{1.111 \times 0.833}\]

\[= \text{₪}180 + \frac{\text{₪}400}{0.925} = \text{₪}180 + \text{₪}432.4 = \mathbf{\text{₪}612.4}\]

Even though you are spending efficiently, being delayed stretches the trip — extra waiting time at checkpoints means more fuel idling, more snacks, more cost. You will arrive ₪12.4 over budget.

EAC Formula 4 — Fresh estimate from this point forward

“I will stop at Sebastia ruins on the way — a complete re-plan of the remaining journey. I estimate the rest will cost ₪450 from here.”

\[EAC_4 = AC + ETC_{new} = \text{₪}180 + \text{₪}450 = \mathbf{\text{₪}630}\]

A detour and longer journey means arriving ₪30 over budget — but with memories of an ancient Roman city. This is the bottom-up ETC method: ignore past performance and estimate remaining work fresh.

Tip💡 All Four EAC Forecasts Compared
Formula Assumption EAC vs. BAC (₪600)
EAC₁ = BAC / CPI Same cost efficiency to end ₪540 ✅ ₪60 under
EAC₂ = AC + (BAC − EV) Rest at original budgeted rate ₪580 ✅ ₪20 under
EAC₃ = AC + (BAC−EV)/(CPI×SPI) Same cost and schedule delays ₪612 🟠 ₪12 over
EAC₄ = AC + New ETC Complete re-estimate from now ₪630 🔴 ₪30 over

Which formula should you use? In practice, EAC₁ is the most common (current efficiency is the best predictor of future efficiency). EAC₄ is used after major scope or route changes.

13.5.8 Step 5 — What’s Left and What’s the Final Verdict? (ETC & VAC)

Using EAC₁ = ₪540 (assuming cost efficiency continues):

Estimate to Complete (ETC)

How much money do you still need to reach Jenin?

\[ETC = EAC - AC = \text{₪}540 - \text{₪}180 = \mathbf{\text{₪}360}\]

You have ₪360 left to spend to complete the remaining 40 km of your journey.

Variance at Completion (VAC)

What will your final saving (or overrun) be compared to the original budget?

\[VAC = BAC - EAC = \text{₪}600 - \text{₪}540 = \mathbf{+\text{₪}60}\]

A positive VAC means you will finish ₪60 under budget. That is ₪60 saved — enough for a warm meal in Jenin when you arrive! 🍽️

13.8 Cost Control 📋 Required

Cost control involves monitoring, forecasting, and taking corrective action:

13.8.1 Cost Control Techniques

  • EVM Trending
  • Cost Forecasting
  • Change Control
  • Recovery Strategies

Monitor CPI and SPI trends weekly: - Is CPI improving or deteriorating? - Historical research shows: CPI rarely improves by more than 10% from its value at 20% project completion - Early warning: CPI < 0.9 at 20% completion = high overrun risk

Review EAC regularly and communicate honestly: - EAC = BAC/CPI — if current cost performance continues (most common) - EAC = AC + (BAC−EV) — if remaining work will be done at original budget - EAC = AC + ETC — if an independent re-estimate of remaining work is done

Compare all three forecasts monthly — divergence signals problems.

All cost changes must go through formal change control: 1. Identify cost trending beyond threshold (typically ±5%) 2. Issue early warning notice to client 3. Raise formal change request 4. Get written approval before spending additional funds

When the project is over budget: 1. Value Engineering — achieve same outcome at lower cost 2. Scope reduction — formally remove lower-priority deliverables 3. Productivity improvement — identify and remove bottlenecks 4. Procurement re-negotiation — re-tender over-budget packages 5. Request Management Reserve — request release from sponsor

13.9 Project Portfolio Management (PPM) 📋 Required

Project Portfolio Management (PPM) is the centralised management of one or more portfolios — groups of projects, programmes, and operations — to achieve strategic business objectives.

Note📖 Portfolio vs. Programme vs. Project
Level Scope Focus
Portfolio Collection of projects/programmes aligned to strategic goals Strategic value, resource optimisation, balance
Programme Group of related projects managed together for benefits Synergies, shared resources, coordinated delivery
Project Temporary endeavour to create a unique product/service Defined scope, schedule, and budget

A portfolio may contain programmes and stand-alone projects. Not all projects in a portfolio need to be related to each other.

13.9.1 Why PPM Matters for Cost Management

PPM extends cost management from the individual project level to the organisational level — ensuring money is invested in the right projects:

13.9.2 Benefits of Project Portfolio Management

Benefit Description
Strategic alignment Ensures every funded project supports organisational goals
Resource optimisation Avoids over-commitment; balances demand with capacity
Risk diversification A portfolio of projects spreads risk like a financial portfolio
Kill decisions Enables conscious decisions to stop projects that no longer deliver value
Transparency Senior leadership gets a consolidated view of total cost and benefit
Prioritisation When budgets are cut, PPM provides the framework to decide which projects survive

### 3. Additional Cost Classifications

| Cost Type | Definition | Key Rule / Example |
|-----------|------------|--------------------|
| **Sunk Costs** | Money already spent and **unrecoverable** | ⚠️ Never let sunk costs influence future decisions — e.g. funds spent on a cancelled prototype or a failed software platform |
| **Opportunity Costs** | The potential value or revenue **lost by choosing one project over an alternative** | Choosing Project A means forgoing the benefit Project B would have delivered |
| **Recurring Costs** | Repetitive expenses incurred regularly | Weekly labour costs, monthly software subscriptions |
| **Non-Recurring Costs** | One-time upfront investments | Initial hardware setup, site mobilisation |
| **Quality Costs** | Expenses dedicated to ensuring quality standards are met | **Prevention** (training), **Appraisal** (testing), **Failure** (rework, warranty claims) |
| **Contingency Reserves** | Funds set aside for **known risks** or scope changes within the project's baseline budget | Controlled by the PM; part of the cost baseline |

::: {.callout-important icon="false"}
## ⚠️ The Sunk Cost Trap

A common decision-making error is allowing sunk costs to drive future spending. The fact that ₪500,000 has already been spent on a failing system is **irrelevant** to the question of whether to continue — only the future costs and benefits of each option should guide the decision.
:::

## Life Cycle Costing

**Life cycle costing (LCC)** considers the **total cost of ownership** across the asset's entire life — not just the capital construction cost:

$$LCC = C_{initial} + C_{operations} + C_{maintenance} + C_{disposal} - C_{salvage}$$

::: {.callout-important icon="false"}
## ⚠️ Why LCC Matters

A pump that costs $8,000 to purchase but $3,000/year to maintain over 20 years has a life cycle cost of:
$$LCC = \$8,000 + (20 \times \$3,000) = \$68,000$$

A $12,000 pump requiring only $1,200/year has:
$$LCC = \$12,000 + (20 \times \$1,200) = \$36,000$$

The "cheaper" pump costs **89% more** over its service life. LCC prevents false economy in procurement.
:::

## Financial Return Concepts

Senior management and clients evaluate projects using financial metrics. Project managers must speak this language:

| Term | Definition | Formula |
|------|------------|---------|
| **Revenue** | Income generated from the project's outputs | — |
| **Profit** | Revenue minus all expenditures | $Profit = Revenue - Cost$ |
| **Profit margin** | Ratio of profit to revenue (expressed as %) | $PM = \frac{Profit}{Revenue} \times 100$ |
| **Return on Investment (ROI)** | Benefit of investment relative to its cost | $ROI = \frac{(Benefits - Costs)}{Costs} \times 100\%$ |
| **NPV** | Net Present Value — sum of discounted future cash flows | $NPV = \sum \frac{CF_t}{(1+r)^t}$ |
| **Payback Period** | Time to recover initial investment | $PP = \frac{Initial\ Investment}{Annual\ Net\ Benefit}$ |

*A positive NPV means the project creates value. A higher ROI indicates better return per dollar invested.*

## Learning Curve Theory

**Learning curve theory** states that as workers gain experience producing a product, **unit cost decreases in a predictable pattern**. Each time cumulative output doubles, cost per unit falls by a fixed percentage.

$$Unit\ Cost_n = Unit\ Cost_1 \times n^b \quad \text{where } b = \frac{\log(learning\ rate)}{\log(2)}$$

| Learning Rate | Meaning |
|--------------|---------|
| 80% | Each time production doubles, unit cost = 80% of previous |
| 90% | Unit cost = 90% of previous each doubling |

*Example: If the first unit costs $100,000 and the learning rate is 80%, the 2nd unit costs $80,000; the 4th unit costs $64,000; the 8th costs $51,200.*

**Project implication:** Software development, prefabrication, and repetitive construction activities all exhibit learning curve effects — factor this into estimates for repetitive work.

## Reserves

**Reserves** are funds included in a cost estimate to mitigate risk:

| Reserve Type | Purpose | Who Controls |
|-------------|---------|--------------|
| **Contingency Reserve** | Known-unknowns — identified risks with probability and impact | Project Manager |
| **Management Reserve** | Unknown-unknowns — unforeseeable events | Senior Management / Sponsor |

*Contingency is part of the cost baseline; management reserve is NOT in the cost baseline but IS in the project budget.*

:::

## Cost Estimation [📋 Required]{.badge-req}

**Cost estimation** is the process of predicting the financial cost of completing project work.

### Estimation Classes (فئات تقدير التكلفة) — AACE International Standard

The **AACE International Cost Estimate Classification System** categorises capital project cost estimates into five distinct classes (Class 1 through 5) based on the **maturity of project definition deliverables** (نضج مخرجات تعريف المشروع) — not merely elapsed time or estimate purpose. It provides a standardised stage-gate framework that aligns estimate accuracy and methodology with the degree of project scope development.

::: {.callout-note icon="false"}
## 📌 Three Key Rules of the System

1. **Primary determinant is scope maturity** — the class assigned depends on how complete the project definition deliverables are, not the phase name or calendar date.
2. **Accuracy ranges** (نطاق الدقة) **are not universal** — they depend on technological complexity, quality of historical data, and defined risk levels.
3. **Scope changes are excluded** — accuracy percentages represent normal variation *within* a defined scope; they do not cover scope growth.
:::

### Estimation Techniques (أساليب تقدير التكلفة)

::: {.panel-tabset}

## Analogous (Top-Down)
### التقدير بالمقارنة / التناظري (Analogous — Top-Down)

**Based on historical data from similar past projects** — الاعتماد على البيانات التاريخية لمشروع سابق مماثل لتقدير تكلفة أو مدة المشروع الحالي.

$$Cost_{new} = Cost_{historical} \times Adjustment\ Factor$$

| | |
|---|---|
| **When to use** | Very early project stages — **Class 5 / Class 4** — when design details are almost non-existent (المراحل الأولية جداً عندما تكون التفاصيل شبه معدومة) |
| **Advantages (المميزات)** | Very fast · Low cost · Requires minimal engineering effort |
| **Disadvantages (العيوب)** | Very low accuracy — assumes similar conditions, location, and inflation rates, which rarely holds true (يفترض تشابه الظروف والموقع والتضخم، وهو ما لا يحدث غالباً) |

::: {.callout-tip icon="false"}
## 💡 Simple Example — Painting a School Classroom

**Situation:** You need to estimate the cost of painting a new classroom (60 m²). You have no detailed plans yet — only the room size.

**Historical data:** Last year you painted a similar classroom of **50 m²** for **₪2,500**.

**Step 1 — Calculate the historical unit rate:**
$$Unit\ Rate = \frac{\text{₪}2{,}500}{50\ m^2} = \text{₪}50\ per\ m^2$$

**Step 2 — Apply to the new project:**
$$Cost_{new} = \text{₪}50/m^2 \times 60\ m^2 = \mathbf{\text{₪}3{,}000}$$

> **Interpretation:** Based on the last job, painting this classroom should cost around ₪3,000. This took 2 minutes to calculate — but accuracy is only ±30% to ±50%. The real cost could be anywhere from ₪1,500 to ₪4,500 depending on paint quality, number of coats, and labour rates. Use this number only for early budget screening.
:::

**Cost Capacity Factor — Six-Tenths Rule (قاعدة الأعشار الستة):**
$$Cost_B = Cost_A \times \left(\frac{Capacity_B}{Capacity_A}\right)^{0.6}$$

*Engineering example:* A 50 ML/day desalination plant cost $85M. Estimating a 65 ML/day plant:
$$\$85M \times (65/50)^{0.6} = \$85M \times 1.21 \approx \$103M$$

**Accuracy (نطاق الدقة):** ±25% to ±50%

## Parametric
### التقدير البارامتري / الإحصائي (Parametric)

**Uses a statistical relationship between historical data and project parameters** to calculate cost — استخدام علاقة إحصائية بين البيانات التاريخية والمتغيرات الأخرى (البارامترات) لحساب التكلفة، مثل: تكلفة المتر المربع × المساحة الكلية.

$$Cost = Unit\ Rate \times Quantity\ of\ Parameter$$

| | |
|---|---|
| **When to use** | Early to mid stages — **Class 4 / Class 3** — e.g. estimating hospital construction costs based on number of beds (تقدير تكلفة بناء المستشفيات بناءً على عدد الأسرة) |
| **Advantages (المميزات)** | More accurate than analogous estimating · Easy to adjust and scale using software |
| **Disadvantages (العيوب)** | Entirely dependent on model quality — if historical data or equations are wrong, the result will be incorrect (إذا كانت البيانات القديمة أو المعادلات خاطئة، ستكون النتيجة غير صحيحة) |

::: {.callout-tip icon="false"}
## 💡 Simple Example — Painting a School (Multiple Classrooms)

**Situation:** You need to paint an entire school — 12 classrooms, a corridor, and a staff room. You now have the floor plan (areas known) but no detailed specifications. You use published unit rates from similar school projects.

| Area | Unit Rate | Quantity | Estimated Cost |
|------|-----------|----------|----------------|
| Classrooms (standard) | ₪50/m² | 12 × 60 m² = 720 m² | ₪36,000 |
| Corridor (high-traffic, extra coats) | ₪65/m² | 150 m² | ₪9,750 |
| Staff room (feature wall) | ₪80/m² | 40 m² | ₪3,200 |
| **Total Parametric Estimate** | | | **₪48,950** |

> **Interpretation:** The parametric model gives a much better breakdown than the analogous single number. You can see where costs come from — and changing one rate (e.g. if corridor paint is more expensive) instantly updates the total. Accuracy is ±10–25%: far better than the analogous estimate, but a detailed take-off would still be more precise.
:::

**Accuracy (نطاق الدقة):** ±10% to ±25%

## Bottom-Up
### التقدير من أسفل إلى أعلى (Bottom-Up)

**Bottom-up estimating** builds the total project estimate by estimating **each individual task, activity, or work package separately** — then rolling all those estimates upward into a project total.

تفكيك المشروع إلى أصغر أجزاء ممكنة (حزم العمل في هيكل تقسيم العمل WBS) وتخمين تكلفة كل بند على حدة، ثم تجميعها تصاعدياً للوصول لإجمالي المشروع.

| | |
|---|---|
| **When to use** | Advanced, engineering-complete stages — **Class 2 / Class 1** (المراحل المتقدمة والمكتملة هندسياً) |
| **Advantages (المميزات)** | Most accurate technique · Provides full detail supporting cost control during execution (الأدق على الإطلاق، ويوفر تفاصيل كاملة تدعم الرقابة على التكاليف أثناء التنفيذ) |
| **Disadvantages (العيوب)** | Time-consuming · Very costly to prepare · Requires complete engineering documents (يستهلك وقتاً طويلاً، مكلف جداً لإعداده، ويتطلب وثائق هندسية مكتملة) |

::: {.callout-tip icon="false"}
## 💡 Simple Example — Painting One Classroom (Full Detail)

**Situation:** The school contract is now finalised. You must submit a priced tender for painting **one standard classroom (60 m²)**. You count every litre of paint, every hour of labour, every tool.

**Step 1 — Materials (المواد):**

| Item | Quantity | Unit Rate | Cost |
|------|----------|-----------|------|
| Primer coat | 6 litres | ₪8/litre | ₪48 |
| Emulsion paint (2 coats) | 14 litres | ₪12/litre | ₪168 |
| Sandpaper & masking tape | 1 set | ₪15 | ₪15 |
| **Materials subtotal** | | | **₪231** |

**Step 2 — Labour (العمالة):**

| Task | Hours | Rate | Cost |
|------|-------|------|------|
| Surface preparation | 3 hrs | ₪25/hr | ₪75 |
| Priming | 2 hrs | ₪25/hr | ₪50 |
| Painting (2 coats) | 5 hrs | ₪25/hr | ₪125 |
| **Labour subtotal** | | | **₪250** |

**Step 3 — Equipment (المعدات):**

| Item | Days | Rate | Cost |
|------|------|------|------|
| Scaffolding hire | 1 day | ₪40/day | ₪40 |
| **Equipment subtotal** | | | **₪40** |

**Step 4 — Overheads @ 15% (المصاريف العامة):**
$$OH = (\text{₪}231 + \text{₪}250 + \text{₪}40) \times 15\% = \text{₪}521 \times 0.15 = \text{₪}78$$

**Step 5 — Total (one classroom):**

| Component | Cost |
|-----------|------|
| Materials | ₪231 |
| Labour | ₪250 |
| Equipment | ₪40 |

:::

#### The 4-Step Process (خطوات التطبيق)

| Step | Action | What to Do |
|------|--------|-----------|
| **1 — Break Down** (تفكيك المشروع) | Create a WBS (هيكل تقسيم العمل) | Split the project into work packages — the road map of individual tasks to estimate |
| **2 — Estimate Each Package** (تقدير كل حزمة) | Consult team & experts | For each work package, determine time, cost, and resources. Consult developers, engineers, designers |
| **3 — Aggregate** (التجميع التصاعدي) | Sum all estimates | Add all work package estimates to produce the total project cost |
| **4 — Review & Refine** (المراجعة والتحسين) | Validate with stakeholders | Adjust using historical data or expert judgement; confirm with sponsor |

*For each work package — مكوّنات تكلفة كل حزمة عمل:*

1. Materials (المواد): Quantity × Unit rate
2. Labour (العمالة): Hours × Hourly rate
3. Equipment (المعدات): Hours/days × Hire rate
4. Overheads (المصاريف العامة): (L + M + E) × OH%
5. Profit/margin (الربح) — for contractors

#### Benefits (المميزات)

| Benefit | Explanation |
|---------|-------------|
| **High accuracy (دقة عالية)** | No big assumptions — every task is individually examined |
| **Better risk identification (كشف المخاطر مبكراً)** | Task-level breakdown exposes cost and schedule risks before they escalate |
| **Stakeholder confidence (ثقة أصحاب المصلحة)** | Detailed, evidence-based estimates are far easier to defend and gain buy-in for |

#### Drawbacks (العيوب)

| Drawback | Impact |
|----------|--------|
| **Time-consuming (يستغرق وقتاً طويلاً)** | Estimating every task separately is a project in itself for large programmes |
| **Requires many inputs (يحتاج مدخلات كثيرة)** | Coordination across team members, experts, and stakeholders adds overhead |
| **Risk of over-detailing (خطر الإفراط في التفصيل)** | Too deep a WBS decomposition makes estimates hard to track and maintain |

**Accuracy (نطاق الدقة):** ±5% to ±15%

## Three-Point (PERT)
### التقدير ثلاثي النقاط (Three-Point Estimation — PERT)

**A technique to reduce risk and uncertainty** by considering three scenarios instead of a single fixed number — تقنية لتقليل المخاطر وعدم اليقين عبر أخذ ثلاثة سيناريوهات في الاعتبار بدلاً من رقم واحد ثابت.

| Scenario | Symbol | Arabic | Description |
|----------|--------|--------|-------------|
| **Optimistic** | O | المتفائل | Best-case scenario — everything goes perfectly |
| **Most Likely** | M | الأكثر احتمالاً | Realistic scenario under normal conditions |
| **Pessimistic** | P | المتشائم | Worst-case scenario — major risks materialise |

**PERT Weighted Average Formula (المعادلة الموزونة):**

$$CE = \frac{O + 4M + P}{6}$$

The Most Likely estimate is weighted **four times** more than the Optimistic or Pessimistic — reflecting that realistic conditions are far more probable than extremes.

**Standard Deviation (الانحراف المعياري) — measure of uncertainty:**

$$\sigma = \frac{P - O}{6}$$

A large $\sigma$ means high uncertainty; a small $\sigma$ means the three estimates are close together and the outcome is more predictable.

::: {.callout-tip icon="false"}
## 💡 Simple Example — Painting a Classroom: How Long Will It Take?

**Situation:** You are planning to paint the classroom but you are unsure how many days it will take. You ask your painter, who gives you three honest answers:

| Scenario | Symbol | Days | Reasoning |
|----------|--------|------|-----------|
| **Optimistic** | O | **2 days** | Surface is clean, paint arrives on time, no interruptions |
| **Most Likely** | M | **4 days** | Normal conditions — some prep work, one afternoon break |
| **Pessimistic** | P | **10 days** | Wall cracks found, paint delivery delayed, extra coats needed |

**Step 1 — PERT weighted average:**
$$CE = \frac{O + 4M + P}{6} = \frac{2 + (4 \times 4) + 10}{6} = \frac{2 + 16 + 10}{6} = \frac{28}{6} \approx \mathbf{4.67\ days}$$

**Step 2 — Standard deviation (how uncertain is this estimate?):**
$$\sigma = \frac{P - O}{6} = \frac{10 - 2}{6} = \frac{8}{6} \approx \mathbf{1.33\ days}$$

> **Interpretation:** Rather than simply saying "4 days" (most likely), the PERT estimate gives **4.67 days** — pulled upward by the pessimistic scenario. The standard deviation of 1.33 days tells you there is meaningful uncertainty: plan for 5–6 days to be safe. If the painter said O=3, M=4, P=5, the σ would be only 0.33 — very predictable. The wider the gap between O and P, the riskier the estimate.

**Apply to cost:** Using the bottom-up rate of ₪25/hr × 8 hrs/day:
$$CE_{cost} = 4.67\ days \times 8\ hrs \times \text{₪}25/hr = \mathbf{\text{₪}934}$$

vs. the most-likely-only estimate of 4 × 8 × ₪25 = ₪800 — the PERT approach adds ₪134 as implicit risk buffer.
:::

Used to build **cost contingency (ميزانية الطوارئ)** from risk analysis.

**Accuracy (نطاق الدقة):** ±10% to ±15% (when combined with realistic risk data)

:::

## Earned Value Management (EVM) [📋 Required]{.badge-req}

**Earned Value Management (EVM)** integrates scope, schedule, and cost into a single measurement system — giving you an objective view of project status at any point.

### The Three Core EVM Values

::: {.callout-note icon="false"}
## 📖 The Three Fundamental EVM Metrics

| Metric | Acronym | Old Name | Question it Answers |
|--------|---------|----------|---------------------|
| **Planned Value** | PV | BCWS | How much work was *planned* to be done (in $)? |
| **Earned Value** | EV | BCWP | How much work has actually been *accomplished* (in $)? |
| **Actual Cost** | AC | ACWP | How much have we actually *spent* (in $)? |
:::

### Rate of Performance (RP)

**Rate of Performance (RP)** is a practical alternative to the standard EV calculation when the precise % complete of an activity is uncertain. It compares **actual work completed** to the **work that should have been done by now**:

$$RP = \frac{\text{Actual work completed}}{\text{Work planned to be completed}} \times 100\%$$

$$EV = RP \times PV$$

::: {.callout-tip icon="false"}
## 💡 RP Example

Activity A is planned to take 10 days and is budgeted at $5,000. After 5 days (50% of planned time), the team has completed 3 days of work (30% of the planned work).

$$RP = \frac{3}{5} = 60\%$$

$$EV = 60\% \times \$2,500 = \$1,500$$

(Note: $2,500 = PV at status date = 50% of $5,000)

*RP is especially useful for activities where measuring % complete is subjective — it grounds the earned value calculation in planned vs. actual work quantities.*
:::


### EVM Formulas Reference Card

| Metric | Formula | Positive = Good | Negative = Bad |
|--------|---------|-----------------|----------------|
| **SV** (Schedule Variance) | $EV - PV$ | Ahead of schedule | Behind schedule |
| **CV** (Cost Variance) | $EV - AC$ | Under budget | Over budget |
| **SPI** (Schedule Performance Index) | $EV / PV$ | > 1 = ahead | < 1 = behind |
| **CPI** (Cost Performance Index) | $EV / AC$ | > 1 = under budget | < 1 = over budget |
| **EAC** (Estimate at Completion) | $BAC / CPI$ | — | — |
| **ETC** (Estimate to Complete) | $EAC - AC$ | — | — |
| **VAC** (Variance at Completion) | $BAC - EAC$ | Positive = under budget | Negative = over budget |
| **TCPI** (To-Complete Perf. Index) | $(BAC - EV) / (BAC - AC)$ | < 1 = easy | > 1 = needs improvement |

## 🗺️ Before the Numbers: A Story First

EVM can feel like a wall of formulas — until you tie each one to something real. Imagine you are driving from **Tulkarem to Jenin** — two cities in the West Bank, roughly **60 km apart**. You planned the trip carefully, estimated fuel, food, and tolls, and set a budget of **₪10 per km**. You are the project manager of this journey.

$$\text{Budget at Completion (BAC)} = 60\ \text{km} \times \text{₪}10/\text{km} = \text{₪}600$$

### Step 1 — Planning the Trip (PV, EV, AC)

By midday you had planned to cover **24 km** of the route. That is your **Planned Value (PV)** — the budgeted cost of work you planned to accomplish by this point.

$$PV = 24\ \text{km} \times \text{₪}10 = \text{₪}240$$

But in reality, checkpoints and traffic on Road 60 slowed you down. You have only driven **20 km** so far. That is your **Earned Value (EV)** — the value of work you actually completed, expressed in budget terms.

$$EV = 20\ \text{km} \times \text{₪}10 = \text{₪}200$$

Now check your wallet. Fuel, a snack at a roadside stand, and a parking fee at the checkpoint total **₪180** spent. That is your **Actual Cost (AC)**.

$$AC = \text{₪}180$$

::: {.callout-tip icon="false"}
## 📌 Quick Recap — The Three Core Values

| Metric | What It Represents | Value |
|--------|-------------------|-------|
| **PV** — Planned Value | Work you *planned* to do by now | **₪240** (24 km planned) |
| **EV** — Earned Value | Work you *actually completed* | **₪200** (20 km driven) |
| **AC** — Actual Cost | Money you *actually spent* | **₪180** spent |

On paper you should be at 24 km, but you are only at 20 km — yet you have spent less than expected. Let's see what the numbers tell us.
:::

---

### Step 2 — Are You On Schedule? On Budget? (SV & CV)

#### Schedule Variance (SV)

SV tells you whether you are ahead or behind your travel plan.

$$SV = EV - PV = \text{₪}200 - \text{₪}240 = \mathbf{-\text{₪}40}$$

A **negative SV** means you are **behind schedule** — you are 4 km (₪40 worth of distance) behind where you planned to be.

#### Cost Variance (CV)

CV tells you whether you are spending more or less than expected for the work done.

$$CV = EV - AC = \text{₪}200 - \text{₪}180 = \mathbf{+\text{₪}20}$$

A **positive CV** means you are **under budget** — you spent ₪20 less than the budget for the 20 km you have completed. Your roadside snack cost less than expected!

::: {.callout-important icon="false"}
## ⚠️ Variance Summary

| Variance | Formula | Result | Meaning |
|----------|---------|--------|---------|
| **SV** (Schedule Variance) | EV − PV | **−₪40** | 🟠 Behind schedule (4 km behind plan) |
| **CV** (Cost Variance) | EV − AC | **+₪20** | 🟢 Under budget (₪20 saved so far) |

**Rule:** Negative = Bad · Positive = Good · Zero = Exactly on plan
:::

---

### Step 3 — How Efficiently Are You Travelling? (SPI & CPI)

Variances tell you the *gap* in money terms. **Performance indices** tell you the *ratio* — how efficiently you are working compared to the plan. They are unit-free numbers that allow comparisons across projects of any size.

#### Schedule Performance Index (SPI)

$$SPI = \frac{EV}{PV} = \frac{\text{₪}200}{\text{₪}240} = \mathbf{0.833}$$

An SPI of **0.833** means you are completing **83.3%** of the planned distance for every kilometre planned. For every 10 km you should drive, you are only covering about 8.3 km. You are running at 83% of your planned pace.

#### Cost Performance Index (CPI)

$$CPI = \frac{EV}{AC} = \frac{\text{₪}200}{\text{₪}180} = \mathbf{1.111}$$

A CPI of **1.111** means for every **₪1 you spend, you get ₪1.11 worth of distance**. Your driving is cost-efficient — you are stretching the budget beyond what was planned.

::: {.callout-note icon="false"}
## 📊 Index Interpretation Guide

| Index | Value | Condition | Plain English |
|-------|-------|-----------|---------------|
| **SPI** | **0.833** | < 1 ⚠️ Behind schedule | Driving slower than planned — arrive late |
| **CPI** | **1.111** | > 1 ✅ Under budget | Spending less per km than budgeted — saving money |

**EVM tells two stories at once:** How *fast* you are going (SPI) and how *wisely* you are spending (CPI). Here you are running late but saving money — a common real-world situation.
:::

---

### Step 4 — How Will the Whole Trip End? (EAC Forecasts)

So far you have driven 20 km and spent ₪180. You still have **40 km** left to Jenin. What will the **total trip cost** be? EVM offers **four forecasting methods**, each reflecting a different assumption about your future behaviour.

```{=html}
<div style="background:#fef9c3;border-left:5px solid #eab308;border-radius:6px;padding:16px 22px;margin:1em 0;">
  <strong>Known values going into the forecast:</strong>
  BAC = ₪600 · EV = ₪200 · AC = ₪180 · CPI = 1.111 · SPI = 0.833
</div>
```

#### EAC Formula 1 — Current efficiency continues

> *"I have been driving efficiently and plan to keep it that way — same fuel habits, same stops, all the way to Jenin."*

$$EAC_1 = \frac{BAC}{CPI} = \frac{\text{₪}600}{1.111} = \mathbf{\text{₪}540}$$

If you maintain your current cost efficiency for the remaining 40 km, you will arrive in Jenin having spent only **₪540** — saving **₪60** against the original budget.

#### EAC Formula 2 — Early savings were temporary

> *"I was frugal at the start, but from here I will drive at exactly the original budgeted rate — ₪10 per km for the remaining distance."*

$$EAC_2 = AC + (BAC - EV) = \text{₪}180 + (\text{₪}600 - \text{₪}200) = \text{₪}180 + \text{₪}400 = \mathbf{\text{₪}580}$$

You will finish the trip spending **₪580** — still ₪20 under the original budget, but you gave up most of your early savings.

#### EAC Formula 3 — Both schedule and cost delays continue

> *"Checkpoints and slow traffic will follow me all the way. My CPI *and* SPI will remain the same — I am both slow and (luckily) cost-efficient."*

$$EAC_3 = AC + \frac{BAC - EV}{CPI \times SPI} = \text{₪}180 + \frac{\text{₪}400}{1.111 \times 0.833}$$

$$= \text{₪}180 + \frac{\text{₪}400}{0.925} = \text{₪}180 + \text{₪}432.4 = \mathbf{\text{₪}612.4}$$

Even though you are spending efficiently, being delayed stretches the trip — extra waiting time at checkpoints means more fuel idling, more snacks, more cost. You will arrive **₪12.4 over budget**.

#### EAC Formula 4 — Fresh estimate from this point forward

> *"I will stop at Sebastia ruins on the way — a complete re-plan of the remaining journey. I estimate the rest will cost ₪450 from here."*

$$EAC_4 = AC + ETC_{new} = \text{₪}180 + \text{₪}450 = \mathbf{\text{₪}630}$$

A detour and longer journey means arriving **₪30 over budget** — but with memories of an ancient Roman city. This is the **bottom-up ETC** method: ignore past performance and estimate remaining work fresh.

::: {.callout-tip icon="false"}
## 💡 All Four EAC Forecasts Compared

| Formula | Assumption | EAC | vs. BAC (₪600) |
|---------|-----------|-----|----------------|
| **EAC₁** = BAC / CPI | Same cost efficiency to end | **₪540** | ✅ **₪60 under** |
| **EAC₂** = AC + (BAC − EV) | Rest at original budgeted rate | **₪580** | ✅ **₪20 under** |
| **EAC₃** = AC + (BAC−EV)/(CPI×SPI) | Same cost *and* schedule delays | **₪612** | 🟠 **₪12 over** |
| **EAC₄** = AC + New ETC | Complete re-estimate from now | **₪630** | 🔴 **₪30 over** |

*Which formula should you use?* In practice, **EAC₁** is the most common (current efficiency is the best predictor of future efficiency). **EAC₄** is used after major scope or route changes.
:::

---

### Step 5 — What's Left and What's the Final Verdict? (ETC & VAC)

Using **EAC₁ = ₪540** (assuming cost efficiency continues):

#### Estimate to Complete (ETC)

How much money do you still need to reach Jenin?

$$ETC = EAC - AC = \text{₪}540 - \text{₪}180 = \mathbf{\text{₪}360}$$

You have **₪360 left to spend** to complete the remaining 40 km of your journey.

#### Variance at Completion (VAC)

What will your final saving (or overrun) be compared to the original budget?

$$VAC = BAC - EAC = \text{₪}600 - \text{₪}540 = \mathbf{+\text{₪}60}$$

A positive VAC means you will finish **₪60 under budget**. That is ₪60 saved — enough for a warm meal in Jenin when you arrive! 🍽️

### Cost Control Techniques

::: {.panel-tabset}

## EVM Trending
Monitor CPI and SPI trends weekly:
- Is CPI improving or deteriorating?
- Historical research shows: **CPI rarely improves by more than 10%** from its value at 20% project completion
- Early warning: CPI < 0.9 at 20% completion = high overrun risk

## Cost Forecasting
Review EAC regularly and communicate honestly:
- **EAC = BAC/CPI** — if current cost performance continues (most common)
- **EAC = AC + (BAC−EV)** — if remaining work will be done at original budget
- **EAC = AC + ETC** — if an independent re-estimate of remaining work is done

Compare all three forecasts monthly — divergence signals problems.

## Change Control
All cost changes must go through formal change control:
1. Identify cost trending beyond threshold (typically ±5%)
2. Issue early warning notice to client
3. Raise formal change request
4. Get written approval before spending additional funds

## Recovery Strategies
When the project is over budget:
1. **Value Engineering** — achieve same outcome at lower cost
2. **Scope reduction** — formally remove lower-priority deliverables
3. **Productivity improvement** — identify and remove bottlenecks
4. **Procurement re-negotiation** — re-tender over-budget packages
5. **Request Management Reserve** — request release from sponsor

## Project Portfolio Management (PPM) [📋 Required]{.badge-req}

**Project Portfolio Management (PPM)** is the centralised management of one or more portfolios — groups of projects, programmes, and operations — to achieve strategic business objectives.

::: {.callout-note icon="false"}
## 📖 Portfolio vs. Programme vs. Project

| Level | Scope | Focus |
|-------|-------|-------|
| **Portfolio** | Collection of projects/programmes aligned to strategic goals | Strategic value, resource optimisation, balance |
| **Programme** | Group of related projects managed together for benefits | Synergies, shared resources, coordinated delivery |
| **Project** | Temporary endeavour to create a unique product/service | Defined scope, schedule, and budget |

*A portfolio may contain programmes and stand-alone projects. Not all projects in a portfolio need to be related to each other.*
:::

### Why PPM Matters for Cost Management

PPM extends cost management from the individual project level to the **organisational level** — ensuring money is invested in the right projects:

```{mermaid}
%%| fig-cap: "PPM connects project costs to organisational strategy"
%%{init: {'flowchart': {'nodeSpacing': 30, 'rankSpacing': 50}}}%%
flowchart TD
    S["🎯 Strategic Objectives<br/>Grow revenue / Cut costs /<br/>Regulatory compliance"] --> PP
    PP["📋 Portfolio Planning<br/>Identify, categorise,<br/>and prioritise projects"] --> RA
    RA["💰 Resource & Budget Allocation<br/>Distribute limited funds<br/>across competing projects"] --> PM
    PM["📊 Portfolio Monitoring<br/>Track aggregate EVM,<br/>costs, and benefits"] --> RV
    RV["🔄 Portfolio Review<br/>Kill / accelerate / add<br/>projects based on value"]
    RV --> PP

    style S fill:#1d4ed8,color:#fff
    style RA fill:#b45309,color:#fff
```

### Benefits of Project Portfolio Management

| Benefit | Description |
|---------|-------------|
| **Strategic alignment** | Ensures every funded project supports organisational goals |
| **Resource optimisation** | Avoids over-commitment; balances demand with capacity |
| **Risk diversification** | A portfolio of projects spreads risk like a financial portfolio |
| **Kill decisions** | Enables conscious decisions to stop projects that no longer deliver value |
| **Transparency** | Senior leadership gets a consolidated view of total cost and benefit |
| **Prioritisation** | When budgets are cut, PPM provides the framework to decide which projects survive |

### PPM Scoring and Prioritisation

Organisations often use a **weighted scoring model** to rank projects for funding:

| Criterion | Weight | Project A Score | Project B Score |
|-----------|--------|-----------------|-----------------|
| Strategic alignment | 30% | 8 | 6 |
| NPV / Financial return | 25% | 7 | 9 |
| Risk level (inverse) | 20% | 6 | 8 |
| Implementation feasibility | 15% | 9 | 5 |
| Regulatory compliance | 10% | 10 | 7 |
| **Weighted Total** | **100%** | **7.65** | **7.05** |

*Project A scores higher despite lower NPV — strategic fit and feasibility outweigh pure financial return.*

::: {.callout-tip icon="false"}
## 💡 PPM Software

Modern PPM software (e.g., Microsoft Project Online, Primavera P6 Portfolio, Oracle PPM Cloud) provides:
- Portfolio dashboards with aggregated EVM across all projects
- Resource capacity planning
- Benefits realisation tracking
- Automatic re-prioritisation when budgets change
- Risk-adjusted portfolio views

A 2015 PMI study found only **20% of organisations** have a high level of benefits realization maturity through PPM — organisations with strong PPM deliver **35% more projects on budget**.
:::

::: {.callout-note icon="false"}
## Microsoft Project: Applying Chapter 7 Concepts

With resources and rates assigned in your project file, MS Project can calculate and track costs automatically:

**Tasks to complete in MS Project:**

1. **Verify resource rates** are entered correctly in the Resource Sheet (Std. Rate, Ovt. Rate, Cost/Use, Accrue At = Prorated for most resources)
2. **Add fixed costs**: In Gantt Chart view, right-click a column header → Insert Column → Fixed Cost. Enter any fixed procurement or subcontract costs directly against the relevant task
3. **View the Cost table**: View → Table → Cost. This shows Baseline Cost, Actual Cost, Remaining Cost, and Cost Variance for every task
4. **Check the project total cost**: Project tab → Project Information → Statistics button. Verify the total cost matches your bottom-up estimate
5. **Set the cost baseline** (if not already done): Project → Set Baseline → this freezes Baseline Cost values
6. **Enter progress for 3–4 weeks** of your project (% Complete per task using actual data or the exercise data from Chapter 6 Exercise 6.3)
7. **Generate the Earned Value report**: Report tab → Costs → Earned Value Report. Read off:
   - **PV** (Planned Value / BCWS) — shown as "Baseline Cost" at the status date
   - **EV** (Earned Value / BCWP) — shown as "Earned Value"
   - **AC** (Actual Cost / ACWP) — shown as "Actual Cost"
   - **CPI** and **SPI** — calculated automatically
   - **EAC** (Estimate at Completion) — MS Project uses EAC = BAC / CPI by default
8. **Set the Status Date**: Project tab → Project Information → Status Date. MS Project uses this date when calculating EV metrics — set it to the end of your last reported week
9. **View the Tracking Gantt** and identify tasks where Cost Variance (CV) is negative (over budget). What corrective actions would you recommend?

**Expected outcome:** Your MS Project EV figures should match the manual EVM calculations from the Chapter 7 exercises. Differences of more than 5% indicate a data entry error — check actual start dates and % complete values.
:::
