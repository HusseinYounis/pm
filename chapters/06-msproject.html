11  Microsoft Project — Practical Tool Guide

Chapter 6 · Planning — Practical Tool

Microsoft Project

From blank file to managed project: a step-by-step guide using Microsoft Project 2021 / Microsoft 365, applied to a real engineering case study.

Note🔖 Chapter Status

All sections in this chapter are ➕ Extended content — topics beyond the required source materials (Schwalbe ITPM Ch.1–8), included to provide a complete engineering project management curriculum.

Learning Outcomes

Tip🎯 Learning Outcomes

By the end of this chapter, you will be able to:

  1. Identify all information and documents needed before opening MS Project
  2. Create a project from scratch — calendar, tasks, durations, and dependencies
  3. Add and assign resources (people and equipment) with correct availability and cost rates
  4. Read the Gantt Chart, Network Diagram, and Resource Sheet views
  5. Set a project baseline and track actual progress against it
  6. Generate schedule, resource, and cost reports
  7. Save and share MS Project files in appropriate formats

11.1 Why Use MS Project?

Manual scheduling (spreadsheets, sticky notes, hand-drawn Gantt charts) becomes unmanageable once a project has more than 20–30 activities and multiple resources. Microsoft Project 2021 / Microsoft Project for Microsoft 365 automates:

  • Critical path calculation (updated instantly when you change a duration)
  • Resource allocation and over-allocation detection
  • Cost tracking against baseline
  • Earned Value analysis
  • Professional reporting
Note🖥️ Which Version Does This Chapter Target?

This chapter targets Microsoft Project 2021 (desktop, perpetual licence) and Microsoft Project Plan 3 / Plan 5 (Microsoft 365 subscription). The interface and ribbon are identical in both. Screenshots reference the dark ribbon theme but all steps apply to any colour theme.

Do NOT confuse with: Microsoft Planner (task management only, no scheduling engine) or Microsoft Project Online (web-only, simplified features).

11.2 Before You Open MS Project — What You Need

Opening MS Project without preparation is like starting construction without drawings. Before you create a single task, you must have the following documents ready.

11.2.1 1. Project Charter

The charter gives MS Project its identity. From the charter you extract:

Charter Element Where It Goes in MS Project
Project name File → Info → Project Name
Project start date Project tab → Project Information → Start Date
Approved end date Becomes a deadline constraint on the final milestone
Project sponsor / PM Custom fields or Notes
High-level budget Budget resource (if using cost tracking)

11.2.2 2. Requirements Document

Requirements define what the project must produce. They feed into your WBS — each major requirement typically becomes a WBS Level-2 element (a summary task in MS Project).

11.2.3 3. Work Breakdown Structure (WBS)

Your WBS is the skeleton of your MS Project schedule. Before entering tasks:

  • Number every work package (e.g. 1.1.1, 1.1.2, …)
  • Decide the level of detail you will schedule (typically Level 3–4)
  • Write a one-sentence description for each work package (WBS dictionary)
Important

Rule: Never enter tasks into MS Project that are not in the WBS. If the work is not in the WBS, it is out of scope.

11.2.4 4. Activity List with Durations

For each WBS work package, list the schedule activities with:

  • Duration estimate (from analogous, parametric, or three-point estimation — Chapter 4)
  • Type: Fixed Duration / Fixed Work / Fixed Units
  • Predecessor activity numbers and dependency type (FS, SS, FF, SF) with any lags

11.2.5 5. Resource Register

Every person, piece of equipment, or material cost that will be assigned to a task must be in your resource register before you begin assigning. Collect:

Resource Field Example
Resource name Ahmed Al-Khalidi
Resource type Work (human) / Material / Cost
Max units (availability) 100% = full time; 50% = half time
Standard rate ₪ 150 / hour
Overtime rate ₪ 225 / hour
Cost/use (fixed fee per use) ₪ 500 per site visit
Calendar Standard / Night Shift / custom

11.2.6 6. Project Calendar and Constraints

Define: - Working days: e.g., Sunday–Thursday (Palestinian / regional calendar) - Non-working days: public holidays, Eid, Ramadan considerations - Fixed date constraints: contractual milestones, permit expiry dates

11.3 The MS Project Interface

🖥️ Main Interface Areas

MS Project 2021 has five main interface zones:

  1. Ribbon (top) — Task, Resource, Report, Project, View, Format tabs
  2. View Bar / Timeline (below ribbon) — optional high-level summary bar
  3. Entry Table (left panel) — spreadsheet of tasks/resources/assignments
  4. Chart/Diagram (right panel) — Gantt bars, network nodes, or histograms
  5. Status Bar (bottom) — mode, zoom slider, new task mode indicator

11.3.1 Key Views

View How to Open Best Used For
Gantt Chart View → Gantt Chart Day-to-day task entry and schedule review
Network Diagram View → Network Diagram Visualising dependencies and critical path
Resource Sheet View → Resource Sheet Entering and editing all resources
Resource Usage View → Resource Usage Detecting over-allocation
Task Usage View → Task Usage Seeing assignments per task
Tracking Gantt View → Tracking Gantt Comparing actual vs. baseline
Reports Report tab Generating printable reports

11.4 Step-by-Step: Creating a Project from Scratch

The following steps follow a logical sequence — do not skip steps or change the order, especially steps 5–6 (tasks before resources).

11.4.1 Step 1 — Create a New File

  1. Open MS Project → File → New → Blank Project
  2. Immediately save: File → Save As → choose location → name the file (e.g., CampusWiFi_v1.mpp)
Tip

File naming convention: [ProjectCode]_[Description]_v[version].mpp
Example: AAUP-IT-01_WiFiUpgrade_v1.mpp

11.4.2 Step 2 — Set Project Information

Go to Project tab → Project Information:

Field Action
Start Date Enter the project start date (e.g., 01 Sep 2025)
Schedule From Leave as “Project Start Date” (forward scheduling)
Current Date Today’s date (auto-filled)
Calendar Select or create (see Step 3)
Priority Leave at 500 (used for resource levelling)

Click Statistics button at any time to see summary: start, finish, duration, work, cost.

11.4.3 Step 3 — Create a Custom Calendar

Project tab → Change Working Time → Create New Calendar

  1. Name it (e.g., “Palestine Standard”)
  2. Set working days: Sunday to Thursday, 08:00–17:00 (with 1-hour lunch break)
  3. Set Friday and Saturday as non-working days
  4. Add exceptions (public holidays):
    • Select the date on the calendar
    • Click Exceptions tab → enter name → set as non-working

11.4.4 Step 4 — Set Up the WBS / Summary Tasks

In the Gantt Chart view, enter your WBS phases as Summary Tasks:

  1. Type the Phase 1 name (e.g., Initiation) in the Task Name column → press Enter
  2. Type sub-tasks below it
  3. Select the sub-tasks → Task tab → Indent Task (or press Alt+Shift+Right arrow)
  4. The parent row becomes a summary task (bold, with a collapse arrow)
Tip

Keyboard shortcut: Alt+Shift+→ to indent (make child), Alt+Shift+← to outdent (make parent)

Structure your task list to mirror the WBS numbering:

1. Project: Smart Campus Wi-Fi Upgrade          ← Project Summary (auto)
   1. Initiation                                 ← Summary Task
      1.1 Develop Project Charter
      1.2 Stakeholder Register
      1.3 Kick-off Meeting                       ← Milestone
   2. Planning                                   ← Summary Task
      2.1 Network Site Survey
      2.2 Equipment Specification
      ...

11.4.5 Step 5 — Enter Durations

Click the Duration column next to each task and type: - 5d = 5 days - 3w = 3 weeks - 0d = milestone (diamond on Gantt) - 1w 2d = 1 week + 2 days = 7 days

Important

Task Mode: Check the Task Mode column. Set to Manually Scheduled only for tasks with fixed dates (e.g., contractual milestones). All other tasks should be Auto Scheduled so MS Project recalculates the schedule automatically when dependencies change.

11.4.6 Step 6 — Set Dependencies (Predecessors)

In the Predecessors column, type the row number of the predecessor task:

To create this Type in Predecessors column
Finish-to-Start (default) 3 (task 3 must finish before this starts)
Finish-to-Start + 2 day lag 3FS+2d
Start-to-Start 3SS
Finish-to-Finish 3FF
Start-to-Start + 1 week lag 3SS+1w
Multiple predecessors 3,5,7

Alternatively, in Gantt Chart view, drag from the end of one task bar to the start of another to create a FS dependency.

Warning

Critical Path Check: After entering all dependencies, go to View → Gantt Chart and check Format → Critical Tasks (check the box). All critical path tasks will turn red. If your entire project is red, you likely have no dependencies set.

11.4.7 Step 7 — Enter Resources

Switch to Resource Sheet view (View tab → Resource Sheet):

Fill in one row per resource:

Column Guidance
Resource Name Full name or role (e.g., “Network Engineer”)
Type Work / Material / Cost
Material Label (for materials only, e.g., “m²”, “units”)
Initials Auto-filled; can customise
Group Department or team (e.g., “IT”, “Civil”)
Max. Units 100% = full time; 50% = part time
Std. Rate e.g., ₪120/h
Ovt. Rate e.g., ₪180/h
Cost/Use Fixed cost each time resource is used
Accrue At Start / End / Prorated (how cost is recorded)
Base Calendar Which working calendar applies to this person

11.4.8 Step 8 — Assign Resources to Tasks

Switch back to Gantt Chart view. For each task:

  1. Double-click the task → Task Information dialog → Resources tab
  2. Select the resource name from the dropdown
  3. Set Units (e.g., 100% for full time on this task, 50% for half time)
  4. Click OK

Or use the Assign Resources button (Resource tab) to drag and assign multiple resources at once.

Note

Over-allocation indicator: A red person icon appears in the Indicators column when a resource is assigned more than their Max. Units. Fix with: Resource tab → Level Resources or manually adjust assignments.

11.4.9 Step 9 — Set the Baseline

Before any work begins, freeze the plan:

Project tab → Set Baseline → Set Baseline

This saves the current schedule as Baseline 0. You can compare actual progress against this later. MS Project allows up to 11 baselines (Baseline 0–10).

Important

Set the baseline only when the plan is approved. Once work begins, do not reset the baseline unless formally approved through change control.

11.4.10 Step 10 — Track Progress

As work proceeds, update the schedule:

  1. Mark % complete: Click a task → Task tab → Mark on Track (sets 100% on track) or type % in the % Complete column
  2. Enter actual dates: Double-click task → Advanced tab → enter Actual Start / Actual Finish
  3. Update remaining duration: In the Tracking Gantt, right-click a task → Update Task → enter remaining work

To see schedule variance: View → Tracking Gantt — the black baseline bar appears below the blue (current) bar.

11.5 MS Project Files — Types and Usage

Extension Name When to Use
.mpp MS Project file Primary working file — always keep this
.mpt MS Project template Save a blank configured project as a reusable template
.mpx MS Project Exchange Legacy export for older systems (rarely needed)
.xml XML export Share with non-MS Project tools
.pdf PDF export Share Gantt charts / reports with stakeholders
.xlsx Excel export Share task lists or cost data with Excel users
.csv CSV export Import/export task or resource data
Tip

Best practice: Maintain three file versions: 1. ProjectName_Working.mpp — your live planning file (updated daily/weekly) 2. ProjectName_Baseline_v1.mpp — locked copy taken at project approval 3. ProjectName_Reports/ — folder of exported PDFs for stakeholder distribution

11.7 Reports in MS Project

MS Project generates professional reports directly from the schedule data. Access via the Report tab.

Report Location What It Shows
Project Overview Report → Dashboards % complete, milestones, upcoming tasks
Work Overview Report → Dashboards Planned vs. actual work per resource
Cost Overview Report → Dashboards Budget vs. actual cost, EV indicators
Upcoming Tasks Report → In Progress Next 28 days of work
Slipping Tasks Report → In Progress Tasks running late vs. baseline
Critical Tasks Report → In Progress Critical path tasks only
Resource Overview Report → Resources Hours by resource — over-allocation
Earned Value Report → Costs PV, EV, AC, CPI, SPI, EAC
Milestone Report Report → In Progress All milestones and their status
Tip

For stakeholder reporting: Use Report → Dashboards → Project Overview and export as PDF. This gives a clean, one-page summary without exposing the full schedule detail.

11.8 Common Mistakes to Avoid

Warning⚠️ Top 10 MS Project Mistakes
  1. Starting without a WBS — tasks entered randomly, no structure, impossible to track
  2. All tasks manually scheduled — MS Project cannot recalculate; schedule is just a static table
  3. No dependencies set — tasks float freely; critical path cannot be calculated
  4. Assigning resources before entering all tasks — resource data becomes inconsistent
  5. Never setting a baseline — no way to compare actual vs. planned
  6. Ignoring over-allocation warnings — red resource icons are serious; they mean your plan is unrealistic
  7. Updating % complete without entering actual dates — creates misleading tracking data
  8. Not using a custom calendar — default calendar is Mon–Fri, which is wrong for regional projects
  9. Using MS Project as a spreadsheet — typing static dates instead of letting the scheduling engine calculate them
  10. One file for all versions — always version your file; never overwrite the baseline file

11.9 Exercises

Caution✏️ Exercise 6.1 — Pre-Project Checklist

Before building a schedule in MS Project, a project manager must collect specific information. For the following project scenario, complete all six preparation documents:

Scenario: Your company has won a contract to design and install a solar power system (50 kW) on the roof of a hospital in Ramallah. The project runs for 12 weeks starting 1 March 2026, budget ₪ 280,000.

  1. Write a one-page Project Charter with: objectives, scope, out-of-scope items, key milestones, sponsor, PM, and approved budget
  2. Create a WBS with at least 3 levels (minimum 20 work packages)
  3. Develop an Activity List with durations and dependencies for all Level-3 WBS items
  4. Create a Resource Register for at least 6 resources (mix of people, equipment, material)
  5. List the project calendar exceptions (holidays) for the project period
  6. Identify 3 fixed-date constraints and explain how you would model each in MS Project
Caution✏️ Exercise 6.2 — Build the Schedule in MS Project

Using the preparation documents from Exercise 6.1 (or the template provided by your instructor):

  1. Create a new MS Project file with a custom calendar (Sunday–Thursday, 08:00–17:00)
  2. Enter all tasks with correct WBS indentation (summary tasks and sub-tasks)
  3. Set all tasks to Auto Scheduled mode
  4. Enter durations and predecessor dependencies
  5. Enter all resources in the Resource Sheet (at least 6 resources with correct types and rates)
  6. Assign resources to all tasks
  7. Identify the critical path (Format → Critical Tasks). List all critical tasks and the total project duration
  8. Check for resource over-allocation and resolve at least one conflict using resource levelling
  9. Set the baseline (Project → Set Baseline → Baseline 0)
  10. Export the Gantt Chart as a PDF and the resource cost summary as an Excel file
Caution✏️ Exercise 6.3 — Progress Tracking

Using the schedule you built in Exercise 6.2, simulate 4 weeks of execution:

Week 1 actual data: - All initiation tasks completed on time (100%) - Site survey started 2 days late (actual start = Day 3)

Week 2 actual data: - Site survey completed (3 days instead of planned 5 days — ahead of schedule) - Procurement task started as planned

Week 3 actual data: - Procurement delayed: expected to take 14 days instead of 10 (vendor delayed delivery)

Week 4 actual data: - Procurement still in progress (60% complete) - IP & VLAN Design completed on time

  1. Enter all actual data using the Update Tasks feature and % Complete column
  2. View the Tracking Gantt — which tasks show schedule variance?
  3. Calculate SPI and CPI using the Earned Value report
  4. Identify which activity is now on the critical path due to the procurement delay
  5. Propose a recovery plan: what can be done to bring the project back on track?
Caution✏️ Exercise 6.4 — Reports and Communication

Using your completed MS Project file:

  1. Generate the Project Overview Dashboard report — export as PDF
  2. Generate the Slipping Tasks report — identify all tasks currently behind baseline
  3. Generate the Resource Overview report — identify the most over-allocated resource
  4. Generate the Earned Value report — extract PV, EV, AC, CPI, SPI values for Week 4
  5. Create a custom one-page stakeholder report using the Report Designer (Report tab → New Report → Table) that shows: Task name, Baseline Start, Actual Start, Baseline Finish, % Complete, Cost Variance
  6. Export the task list (File → Save As → Excel Workbook) and format it as a progress table suitable for a weekly status meeting

### 1. Project Charter

The charter gives MS Project its identity. From the charter you extract:

| Charter Element | Where It Goes in MS Project |
|---|---|
| Project name | File → Info → Project Name |
| Project start date | Project tab → Project Information → Start Date |
| Approved end date | Becomes a deadline constraint on the final milestone |
| Project sponsor / PM | Custom fields or Notes |
| High-level budget | Budget resource (if using cost tracking) |

### 2. Requirements Document

Requirements define what the project must produce. They feed into your **WBS** — each major requirement typically becomes a WBS Level-2 element (a summary task in MS Project).

### 3. Work Breakdown Structure (WBS)

Your WBS is the **skeleton** of your MS Project schedule. Before entering tasks:

- Number every work package (e.g. 1.1.1, 1.1.2, …)
- Decide the level of detail you will schedule (typically Level 3–4)
- Write a one-sentence description for each work package (WBS dictionary)

::: {.callout-important}
**Rule:** Never enter tasks into MS Project that are not in the WBS. If the work is not in the WBS, it is out of scope.
:::

### 4. Activity List with Durations

For each WBS work package, list the **schedule activities** with:

- Duration estimate (from analogous, parametric, or three-point estimation — Chapter 4)
- Type: Fixed Duration / Fixed Work / Fixed Units
- Predecessor activity numbers and dependency type (FS, SS, FF, SF) with any lags

### 5. Resource Register

Every person, piece of equipment, or material cost that will be assigned to a task must be in your resource register before you begin assigning. Collect:

| Resource Field | Example |
|---|---|
| Resource name | Ahmed Al-Khalidi |
| Resource type | Work (human) / Material / Cost |
| Max units (availability) | 100% = full time; 50% = half time |
| Standard rate | ₪ 150 / hour |
| Overtime rate | ₪ 225 / hour |
| Cost/use (fixed fee per use) | ₪ 500 per site visit |
| Calendar | Standard / Night Shift / custom |

### 6. Project Calendar and Constraints

Define:
- **Working days**: e.g., Sunday–Thursday (Palestinian / regional calendar)
- **Non-working days**: public holidays, Eid, Ramadan considerations
- **Fixed date constraints**: contractual milestones, permit expiry dates

## Step-by-Step: Creating a Project from Scratch

The following steps follow a **logical sequence** — do not skip steps or change the order, especially steps 5–6 (tasks before resources).

### Step 1 — Create a New File

1. Open MS Project → **File → New → Blank Project**
2. Immediately save: **File → Save As** → choose location → name the file (e.g., `CampusWiFi_v1.mpp`)

::: {.callout-tip}
**File naming convention:** `[ProjectCode]_[Description]_v[version].mpp`  
Example: `AAUP-IT-01_WiFiUpgrade_v1.mpp`
:::

### Step 2 — Set Project Information

Go to **Project tab → Project Information**:

| Field | Action |
|---|---|
| Start Date | Enter the project start date (e.g., 01 Sep 2025) |
| Schedule From | Leave as "Project Start Date" (forward scheduling) |
| Current Date | Today's date (auto-filled) |
| Calendar | Select or create (see Step 3) |
| Priority | Leave at 500 (used for resource levelling) |

Click **Statistics** button at any time to see summary: start, finish, duration, work, cost.

### Step 3 — Create a Custom Calendar

**Project tab → Change Working Time → Create New Calendar**

1. Name it (e.g., "Palestine Standard")
2. Set working days: **Sunday to Thursday, 08:00–17:00** (with 1-hour lunch break)
3. Set Friday and Saturday as non-working days
4. Add exceptions (public holidays):
   - Select the date on the calendar
   - Click **Exceptions** tab → enter name → set as non-working

### Step 4 — Set Up the WBS / Summary Tasks

In the **Gantt Chart** view, enter your WBS phases as **Summary Tasks**:

1. Type the Phase 1 name (e.g., `Initiation`) in the Task Name column → press Enter
2. Type sub-tasks below it
3. Select the sub-tasks → **Task tab → Indent Task** (or press Alt+Shift+Right arrow)
4. The parent row becomes a summary task (bold, with a collapse arrow)

::: {.callout-tip}
**Keyboard shortcut:** Alt+Shift+→ to indent (make child), Alt+Shift+← to outdent (make parent)
:::

Structure your task list to mirror the WBS numbering:

```
1. Project: Smart Campus Wi-Fi Upgrade          ← Project Summary (auto)
   1. Initiation                                 ← Summary Task
      1.1 Develop Project Charter
      1.2 Stakeholder Register
      1.3 Kick-off Meeting                       ← Milestone
   2. Planning                                   ← Summary Task
      2.1 Network Site Survey
      2.2 Equipment Specification
      ...
```

### Step 5 — Enter Durations

Click the **Duration** column next to each task and type:
- `5d` = 5 days
- `3w` = 3 weeks
- `0d` = milestone (diamond on Gantt)
- `1w 2d` = 1 week + 2 days = 7 days

::: {.callout-important}
**Task Mode:** Check the Task Mode column. Set to **Manually Scheduled** only for tasks with fixed dates (e.g., contractual milestones). All other tasks should be **Auto Scheduled** so MS Project recalculates the schedule automatically when dependencies change.
:::

### Step 6 — Set Dependencies (Predecessors)

In the **Predecessors** column, type the row number of the predecessor task:

| To create this | Type in Predecessors column |
|---|---|
| Finish-to-Start (default) | `3` (task 3 must finish before this starts) |
| Finish-to-Start + 2 day lag | `3FS+2d` |
| Start-to-Start | `3SS` |
| Finish-to-Finish | `3FF` |
| Start-to-Start + 1 week lag | `3SS+1w` |
| Multiple predecessors | `3,5,7` |

Alternatively, in **Gantt Chart view**, drag from the end of one task bar to the start of another to create a FS dependency.

::: {.callout-warning}
**Critical Path Check:** After entering all dependencies, go to **View → Gantt Chart** and check **Format → Critical Tasks** (check the box). All critical path tasks will turn red. If your entire project is red, you likely have no dependencies set.
:::

### Step 7 — Enter Resources

Switch to **Resource Sheet** view (View tab → Resource Sheet):

Fill in one row per resource:

| Column | Guidance |
|---|---|
| Resource Name | Full name or role (e.g., "Network Engineer") |
| Type | Work / Material / Cost |
| Material Label | (for materials only, e.g., "m²", "units") |
| Initials | Auto-filled; can customise |
| Group | Department or team (e.g., "IT", "Civil") |
| Max. Units | 100% = full time; 50% = part time |
| Std. Rate | e.g., ₪120/h |
| Ovt. Rate | e.g., ₪180/h |
| Cost/Use | Fixed cost each time resource is used |
| Accrue At | Start / End / Prorated (how cost is recorded) |
| Base Calendar | Which working calendar applies to this person |

### Step 8 — Assign Resources to Tasks

Switch back to **Gantt Chart** view. For each task:

1. Double-click the task → **Task Information** dialog → **Resources** tab
2. Select the resource name from the dropdown
3. Set **Units** (e.g., 100% for full time on this task, 50% for half time)
4. Click OK

Or use the **Assign Resources** button (Resource tab) to drag and assign multiple resources at once.

::: {.callout-note}
**Over-allocation indicator:** A red person icon appears in the Indicators column when a resource is assigned more than their Max. Units. Fix with: **Resource tab → Level Resources** or manually adjust assignments.
:::

### Step 9 — Set the Baseline

Before any work begins, **freeze** the plan:

**Project tab → Set Baseline → Set Baseline**

This saves the current schedule as **Baseline 0**. You can compare actual progress against this later. MS Project allows up to 11 baselines (Baseline 0–10).

::: {.callout-important}
**Set the baseline only when the plan is approved.** Once work begins, do not reset the baseline unless formally approved through change control.
:::

### Step 10 — Track Progress

As work proceeds, update the schedule:

1. **Mark % complete:** Click a task → Task tab → **Mark on Track** (sets 100% on track) or type % in the % Complete column
2. **Enter actual dates:** Double-click task → Advanced tab → enter Actual Start / Actual Finish
3. **Update remaining duration:** In the Tracking Gantt, right-click a task → Update Task → enter remaining work

To see schedule variance: **View → Tracking Gantt** — the black baseline bar appears below the blue (current) bar.

|---|---|---|

3. `ProjectName_Reports/` — folder of exported PDFs for stakeholder distribution
:::

## Common Mistakes to Avoid

::: {.callout-warning icon="false"}
## ⚠️ Top 10 MS Project Mistakes

1. **Starting without a WBS** — tasks entered randomly, no structure, impossible to track
2. **All tasks manually scheduled** — MS Project cannot recalculate; schedule is just a static table
3. **No dependencies set** — tasks float freely; critical path cannot be calculated
4. **Assigning resources before entering all tasks** — resource data becomes inconsistent
5. **Never setting a baseline** — no way to compare actual vs. planned
6. **Ignoring over-allocation warnings** — red resource icons are serious; they mean your plan is unrealistic
7. **Updating % complete without entering actual dates** — creates misleading tracking data
8. **Not using a custom calendar** — default calendar is Mon–Fri, which is wrong for regional projects
9. **Using MS Project as a spreadsheet** — typing static dates instead of letting the scheduling engine calculate them
10. **One file for all versions** — always version your file; never overwrite the baseline file
:::
